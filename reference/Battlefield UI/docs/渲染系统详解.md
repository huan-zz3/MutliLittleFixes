# Battlefield UI 战场文字渲染系统详解

## 1. 概述

Battlefield UI 是一个在骑马与砍杀2：霸主战场中实时显示**伤害飘字**和**NPC姓名**的 Mod。它的渲染机制建立在游戏的 GauntletUI 框架之上，以“世界坐标 → 屏幕坐标 → UI 控件”的管线将 3D 空间信息投射到 2D 覆盖层上。

**核心机制**：监听 `OnScoreHit` 事件获取伤害数据 → 计算出 3D 世界坐标 → 通过 `MBWindowManager.WorldToScreen` 映射到 2D 屏幕位置 → 通过 GauntletUI 数据绑定更新 UI 控件位置 → 引擎的 `TwoDimensionView` 在每一帧将控件网格渲染到屏幕上。

## 3. 伤害飘字系统

### 3.1 事件入口：OnScoreHit

当战场上发生任何命中时，游戏引擎会调用 `BattlefieldHealthBarView.OnScoreHit`（继承自 `MissionView`），传入以下关键参数：

- `affectedAgent` — 被击中者
- `affectorAgent` — 攻击者（可为 null）
- `blow.InflictedDamage` — 原始伤害值
- `collisionData` — 碰撞数据

### 3.2 过滤规则

在创建伤害文字前执行一系列过滤：

1. **全局开关检查**：`ShowDamageNumbers` 配置项
2. **阵营过滤**：`ShouldDisplayDamageFor()`：
   - 目标是自己 → `ShowMainAgentDamageNumbers`
   - 目标是友军 → `ShowFriendlyDamageNumbers`
   - 目标是敌军 → `ShowEnemyDamageNumbers`
3. **距离过滤**：计算目标眼部位置到摄像机的距离，超过 `DamageNumberMaximumDistance` 则跳过
4. **模式过滤**：仅在 `MissionMode` 为 Battle（2）、Siege（3）、Duel（6）、Captain（7）时生效

### 3.3 伤害值处理

通过 `BattlefieldUIDisplayRules.GetDisplayedDamage()`：
```
return Math.Max(0, inflictedDamage);
```
确保伤害值非负，零伤害不显示。

### 3.4 合并机制（Damage Merging）

为防止短时间内同一目标被快速多次击中导致屏幕被数字淹没，实现了合并窗口：

```
AddOrMergeDamageNumber():
  遍历已激活的伤害条目
  如果存在一个条目满足：
    - 目标 == 当前受击者
    - 年龄 <= DamageNumberMergeWindow (默认0.08秒)
  则：
    - 伤害累加：newDamage = oldDamage + currentDamage（防溢出）
    - 重置 Age = 0
    - 更新世界位置
  否则：
    - 创建新的伤害条目
```

这保证了高频命中（如弓箭连射、快速近战）会将多个小伤害合并为一个展现。

### 3.5 3D → 2D 投影

伤害展现的核心是 `UpdateDamageNumbers()` 中的投影逻辑：

```
// 1. 获取目标当前世界位置（眼睛位置 + 头顶偏移）
worldPosition = agent.GetEyeGlobalPosition() + new Vec3(0, 0, 0.12f, -1f);

// 2. 更新世界位置（目标可能移动）
if (target != null && target.IsActive())
    worldPosition = target.GetEyeGlobalPosition() + new Vec3(0, 0, 0.12f, -1f);

// 3. 通过 CombatCamera 投影到屏幕
float screenX = -10000f, screenY = -10000f, w = -1f;
MBWindowManager.WorldToScreen(CombatCamera, worldPosition, ref screenX, ref screenY, ref w);

// 4. 检查可视性：w > 0 表示在视锥内
if (w <= 0 || !IsValidValue(screenX) || !IsValidValue(screenY))
    → 隐藏

// 5. 应用 UI 位置偏移
item.ScreenPositionX = screenX + horizontalDrift * normalizedAge - 0.5f;
item.ScreenPositionY = screenY - riseDistance * (1 - (1 - t)^2) - 21f;
```

`MBWindowManager.WorldToScreen` 是对 C++ 原生方法 `rglWindowManager::world_to_screen` 的封装。它使用摄像机的 View-Projection 矩阵将 3D 点变换到规范化设备坐标（NDC），再映射到屏幕像素坐标。

**关键点**：该函数使用的摄像机矩阵已经包含了 DLSS 带来的分辨率缩放信息。引擎在内部维护了两个分辨率概念：
- **3D 渲染分辨率**（受 DLSS 影响，可能低于显示分辨率）
- **UI/输出分辨率**（始终是显示器的原生分辨率）

`WorldToScreen` 的最终输出是**UI 层的像素坐标**，以 `Screen.RealScreenResolutionWidth/Height` 为参考系。

### 3.6 动画曲线

伤害飘字的生命周期由两个阶段控制：

| 阶段 | 时间范围 | 效果 |
|------|---------|------|
| 淡入 | 0 ~ 12% 生命周期 | Alpha 线性上升 0→1 |
| 稳定 | 12% ~ 65% 生命周期 | Alpha = 1 |
| 淡出 | 65% ~ 100% 生命周期 | Alpha 线性下降 1→0 |

上浮运动（Y轴偏移）使用易出曲线（ease-out）：
```
t = age / lifetime          // 归一化时间
yOffset = 1 - (1 - t)²     // 二次缓出
```

水平抖动：每个伤害条目分配 `HorizontalDrift = (sequence % 5 - 2) * 7` 像素，使并行多个数字水平错开。

### 3.7 距离衰减

Alpha 值受双重衰减影响：

1. **距离衰减**（`CalculateAlpha`）：
   - 距离 < `FadeStartDistance`：Alpha = 1
   - 距离在 `FadeStartDistance` ~ `MaximumDistance` 之间：线性衰减
   - 距离 >= `MaximumDistance`：Alpha = 0

2. **生命周期衰减**（`CalculateDamageNumberAlpha`）：
   - 最终 Alpha = 距离Alpha × 生命周期Alpha

## 4. NPC姓名/血条系统

### 4.1 Agent 筛选（RefreshVisibleAgents）

每 `RefreshInterval`（默认 0.1 秒）执行一次全量 Agent 筛选：

1. **遍历所有 Agent**，依次检查：
   - `IsEligibleAgent()`：是否为人类、存活、符合阵营显示设置
2. **距离排序**：按到 CombatCamera 的距离升序排列
3. **视锥剔除**：`IsInFrontOfCamera()`：调用 `WorldToScreen` 检查 w > 0
4. **数量上限**：最多 `MaximumVisibleBars` 个

### 4.2 世界坐标 → UI 控件位置（UpdateVisibleItems）

```
// 1. 获取头顶偏移位置
vec = agent.GetEyeGlobalPosition() + new Vec3(0, 0, HeightOffset, -1f);

// 2. 计算距离、透明度、缩放
distance = (vec - camera.Position).Length;
alpha = CalculateAlpha(distance, FadeStartDistance, MaximumDistance);
scale = CalculateMarkerScale(distance, MaximumDistance);

// 3. 投影到屏幕
WorldToScreen(CombatCamera, vec, ref screenX, ref screenY, ref w);

// 4. 设置控件属性
orCreateItem.ScreenPositionX = screenX - 0.5f;      // 居中偏移
orCreateItem.ScreenPositionY = screenY - 18f;        // 垂直偏移
orCreateItem.Alpha = alpha;
orCreateItem.BarWidth = HealthBarWidth * scale;      // 距离缩放
orCreateItem.BarHeight = HealthBarHeight * scale;
```

NPC 名字只在英雄（Hero）身上显示，通过 `IsHero()` 判断：
```
agent.Character as CharacterObject → 检查 HeroObject != null
```

### 4.3 血条的三种样式

通过 `HealthBarCornerStyle` 配置选型，对应 XML 中的三个 Widget：

| 值 | 样式 | Sprite |
|----|------|--------|
| 0 | 直角 | `BlankWhiteSquare_9` |
| 1 | 小圆角 | `rounded_canvas_9` |
| 2 | 大圆角 (默认) | `SquareWRoundedCorners_9` |

内部使用 `FillBarWidget` 子控件，通过 `InitialAmountAsFloat="@HealthRatio"` 绑定血量百分比实现动态填充效果。

### 4.4 名字文本渲染

名字 TextWidget 的 XML 定义：
```xml
<TextWidget
    WidthSizePolicy="Fixed" HeightSizePolicy="Fixed"
    SuggestedWidth="240" SuggestedHeight="22"
    Text="@Name" IsVisible="@ShowName"
    Brush.FontSize="15"
    Brush.TextHorizontalAlignment="Center"
    Brush.TextVerticalAlignment="Bottom"
    ClipContents="false" />
```

关键属性：
- `ClipContents="false"` — 允许文本超出控件宽度，避免长名字被截断
- `TextHorizontalAlignment="Center"` — 相对血条居中显示

## 5. GauntletUI / TwoDimension 渲染管线

### 5.1 初始化流程

```
BattlefieldHealthBarView.OnMissionScreenInitialize()
  → new BattlefieldUIVM()                 // 创建 ViewModel
  → new GauntletLayer("BattlefieldUI", 4) // 创建 UI 层，Order=4
  → layer.LoadMovie("BattlefieldUI", vm)  // 加载 XML Predab，绑定数据
  → MissionScreen.AddLayer(layer)         // 添加到 Mission Screen 的层栈
```

`GauntletLayer` 内部：
```
GauntletLayer(name, localOrder)
  → TwoDimensionView.CreateTwoDimension(name)   // 创建原生 2D 渲染视图
  → new TwoDimensionEnginePlatform(view)         // 创建平台层
  → new UIContext(...)                           // 创建 UI 上下文
  → 加载 SpriteData, FontFactory, BrushFactory   // 加载 UI 资源
```

### 5.2 帧渲染顺序

每一帧引擎按照 Layer 的 Order 排序渲染：

1. **SceneLayer** (Order = -100) — 渲染 3D 场景，应用 DLSS 超分辨率
2. **BattlefieldHealthBarView 的 GauntletLayer** (Order = 4) — 叠加 2D UI

`GauntletLayer.RenderTick(dt)` 的实现：
```
TwoDimensionView.BeginFrame();      // 通知原生引擎开始 2D 帧
TwoDimensionPlatform.OnFrameBegin(); // 重置平台状态
UIContext.RenderTick(dt);           // 渲染所有控件，触发数据绑定更新
TwoDimensionView.EndFrame();        // 提交所有 2D 网格到渲染队列
TwoDimensionPlatform.OnFrameEnd();   // 清理
```

### 5.3 文字绘制过程

当 `TwoDimensionEnginePlatform.DrawText()` 被调用时：

```
DrawText(TextMaterial, TextDrawObject, layer)
  → 获取原生纹理 EngineTexture.Texture
  → 获取或创建文字材质：Material.GetFromResource("two_dimension_text_material")
  → 构造 TwoDimensionTextMeshDrawData：
      - MatrixFrame: 控件变换矩阵（含 ScreenPositionX/Y）
      - ScreenWidth/Height: RealScreenResolutionWidth/Height
      - Color, ScaleFactor, Glow, Outline, Shadow, Blur...
  → 尝试从缓存查找：CreateTextMeshFromCache()
  → 失败则创建新网格：CreateTextMeshFromDescription(顶点/UV/索引数据)
  → 最终 C++ 端执行实际的 DrawIndexedPrimitive 调用
```

**材质**：文字使用专用的 `two_dimension_text_material` 材质，这是一种预先定义好的 UI 文本着色器，支持颜色调制、发光、描边、阴影。该着色器在渲染管线中位于后处理效果之前，因此**不受 DLSS、TAA 等 3D 后处理影响**。

### 5.4 图像绘制过程

血条背景和填充条通过 `DrawImage()` 绘制：

```
DrawImage(SimpleMaterial, ImageDrawObject, layer)
  → 获取原生纹理（EngineTexture.Texture）
  → 获取或创建 WeakMaterial（带 DiffuseMap）
  → 如果启用了叠加纹理（Overlay），设置 use_overlay_texture shader flag
  → 构造 TwoDimensionMeshDrawData：
      - MatrixFrame: 控件变换矩阵
      - ClipRectInfo: 裁剪矩形（ScissorTest）
      - ScreenSize: RealScreenResolution
      - Uvs: 纹理 UV 坐标
      - SpriteSize, NinePatchBorders（九宫格）
      - Color, Alpha, Hue/Saturation/Value 因子
  → View.CreateMeshFromDescription(material, meshDrawData)
```

### 5.5 坐标系统

UI 坐标系统的基本原则：

- **原点**：屏幕左上角 (0, 0)
- **X轴**：向右为正
- **Y轴**：向下为正
- **参考分辨率**：`Screen.RealScreenResolutionWidth × Screen.RealScreenResolutionHeight`

`WorldToScreen` 返回的 `screenX/screenY` 是基于 UI 层的坐标系统，与鼠标位置在同一坐标系中。这意味着无论 DLSS 如何缩放 3D 场景的内部渲染分辨率，UI 坐标始终以显示分辨率为准。

## 6. DLSS 适配详解

### 6.1 DLSS 的工作原理

NVIDIA DLSS（深度学习超级采样）在 Bannerlord 中以 `NativeOptions.NativeOptionsType.DLSS` 枚举项控制。启用时：

1. **3D 场景**以低于显示分辨率的内部分辨率渲染（如 1920x1080 显示器用 1280x720 渲染）
2. 通过 AI 模型将低分辨率帧**超采样**到显示分辨率
3. **UI 层始终以显示分辨率渲染**，不经过 DLSS 处理

### 6.2 DLSS 不直接影响 UI，但 UI 必须适配

关键架构决策：**Bannerlord 的 UI 系统完全运行在原生分辨率空间，不参与 DLSS 的超分辨率管线**。具体体现在：

```
// TwoDimensionEnginePlatform.cs - UI 相关的分辨率
float ITwoDimensionPlatform.Width  => Screen.RealScreenResolutionWidth;   // 显示分辨率
float ITwoDimensionPlatform.Height => Screen.RealScreenResolutionHeight;

// TwoDimensionTextMeshDrawData 中的分辨率
ScreenWidth  = Screen.RealScreenResolutionWidth;   // 始终是显示器原生分辨率
ScreenHeight = Screen.RealScreenResolutionHeight;
```

这意味着：
- UI 像素位置（ScreenPositionX/Y）在 DLSS 开启/关闭时含义相同
- 文字和血条的清晰度不受 DLSS 影响
- **不需要为 DLSS 做特殊处理**

### 6.3 WorldToScreen 与 DLSS 的协同

`WorldToScreen` 函数使用摄像机的 View-Projection 矩阵来确定 3D 点在屏幕上的位置。关键在于：

```
CombatCamera 的投影矩阵
  → 考虑了 DLSS 的分辨率缩放因子
  → 输出已经是 UI 坐标空间的值
  → 无论 DLSS 开启与否，输出的一致性由引擎保证
```

引擎内部处理了 DLSS 分辨率缩放与屏幕像素坐标之间的映射。当 DLSS 开启导致 3D 内部分辨率降低时，`WorldToScreen` 的输出会自动补偿，确保 3D 物体始终与 UI 控件正确对齐。

### 6.4 材质与着色器隔离

Battlefield UI 使用的两种材质：

| 用途 | 材质名称 | 着色器类型 | DLSS 影响 |
|------|---------|-----------|----------|
| 文字 | `two_dimension_text_material` | UI Text Shader | 无 |
| 图形（血条） | 运行时创建（基于 DiffuseMap） | TwoDimension Mesh Shader | 无 |

这两种材质都属于 2D Overlay 着色器类别，在图形管线中于 3D 场景渲染和后处理（包括 DLSS）之后才提交，直接输出到帧缓冲：

```
渲染管线顺序：
1. 3D 场景渲染（DLSS 在此阶段应用低分辨率渲染）
2. 后处理（Bloom, DOF, TAA, DLSS 超采样...）
3. UI/2D 层渲染（原生分辨率，不经过 DLSS）
4. 最终呈现到屏幕
```

### 6.5 拍照模式（Photo Mode）的特殊处理

当 DLSS 开启时进入拍照模式，UI 需要完全隐藏以避免 DLSS 帧合成导致的 UI 残留：

```
OnPhotoModeActivated()
  → this._photoModeActive = true
  → DeactivateDamageNumbers()
  → layer.UIContext.ContextAlpha = 0f       // 将 UI 上下文透明度置零
  // 或者简化：直接不处理 Tick
```

注意 Mod 使用的是 `ContextAlpha = 0f` 而非直接禁用 Layer，这确保了：
- 交互层结构保持
- DLSS 帧合成期间不会有 UI 闪烁
- 退出拍照模式后透明度恢复

### 6.6 小结：适配 DLSS 无需额外代码

Battlefield UI **不需要**为 DLSS 编写任何特殊适配代码，原因：

| 原因 | 说明 |
|------|------|
| 渲染分离 | 2D UI 层与 3D 场景是独立的渲染通道 |
| 坐标系一致性 | UI 始终以显示分辨率为参考系 |
| 引擎封装 | `WorldToScreen` 内部处理了 DLSS 分辨率缩放补偿 |
| 着色器隔离 | UI 着色器在后处理之前/之后执行，不受超采样影响 |
| 原生分辨率保障 | `TwoDimensionEnginePlatform` 始终使用 `RealScreenResolution` |

## 7. 性能优化策略

| 策略 | 实现 | 效果 |
|------|------|------|
| 间隔刷新 | `RefreshInterval` 默认 0.1s 控制 Agent 筛选频率 | 减少每帧 CPU 计算量 |
| 对象池 | `GetOrCreateItem(index)` 和 `AcquireDamageNumberEntry()` 重用 UI 控件 | 避免频繁 GC，降低帧率波动 |
| 距离排序截断 | 先按距离排序，只取前 `MaximumVisibleBars` 个 | 控制每帧渲染负载 |
| 视锥剔除 | `IsInFrontOfCamera` 剔除镜头背后的 Agent | 减少 GPU 提交量 |
| Alpha 裁剪 | Alpha <= 0 的控件直接隐藏，不提交网格 | 减少 GPU draw call |
| 伤害合并 | `DamageNumberMergeWindow` 窗口内伤害合并 | 减少 UI 控件数量 |
| 数量上限 | `MaximumActiveDamageNumbers` 控制最大活跃飘字数 | 防止极端情况性能崩溃 |
| 死对象回收 | `DeactivateDamageNumbers()` 在场景切换、刷新时清空 | 防止僵尸控件残留 |

## 8. 数据流总结

```
[引擎] OnScoreHit()
  │
  ▼
[View]  ShouldDisplayDamageFor() 过滤
  │
  ▼
[View]  AddOrMergeDamageNumber()
  │       → 合并或创建 DamageNumberEntry
  │       → 设置 Item.Text = damage.ToString()
  ▼
[View]  UpdateDamageNumbers(dt)
  │       → 投影 WorldToScreen
  │       → 计算 Alpha、偏移、缩放
  │       → 更新 Item.ScreenPositionX/Y、Alpha、Color
  │       → GauntletUI 通过 Data Binding 同步到控件
  ▼
[Layer] RenderTick()
  │       → UIContext.RenderTick()
  │       → 遍历 Widget Tree
  │       → 触发布局更新和绘制
  ▼
[Platform] TwoDimensionEnginePlatform.DrawText()
  │       → 构造文字网格数据
  │       → 提交到 TwoDimensionView
  ▼
[Engine] rglTwo_dimension_view::EndFrame()
  │       → 提交所有 2D 网格到渲染队列
  │       → 在 3D 场景渲染完成后叠加输出
  ▼
[屏幕] 最终渲染结果
```
